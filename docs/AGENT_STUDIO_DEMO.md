# PleosFlows Agent Workflow Studio · 2026-11-15

## 무엇이 달라졌나요

새 화면 `/agent-studio.html`은 PV5 운영 콘솔이 아니라 **외부 서비스 → Agent Workflow → 승인된 결과**를 중심으로 보여줍니다. Google Sheets와 PLEOS 차량 맥락이 워크플로우에 어떻게 합류하는지 함께 표시합니다. 기존 `/unified.html` 및 Android 소스는 보존했습니다.

## 실행

Node.js 22 이상. 외부 의존성 설치 없음.

```sh
cd pleosflows
npm test
npm start
```

브라우저에서 **http://127.0.0.1:3000/agent-studio.html** 을 엽니다.
기본 페이지 `/`는 원래 차량 데모를 유지합니다. 충돌 시 `PORT=3097 npm start` 후 URL 포트도 변경합니다.

## 촬영 순서 (약 90초)

1. Connectors 탭에서 외부 서비스 카탈로그와 모든 계정의 미연결 표시를 보여줍니다.
2. Workflow Studio에서 Google Calendar → Agent Workflow → 고객 안내/Slack 구조, 아래 Sheets/PLEOS 컨텍스트를 설명합니다.
3. 5분 이하 조건과 모의 ETA 3분을 확인하고 **검토한 구성 저장·활성화** → **모의 이벤트 실행**.
4. 서버가 만든 타임라인을 보여준 뒤 문안을 읽고 **승인·로컬 기록**. 실제 메시지 전송이 아니라는 출력을 보여줍니다.
5. 메신저 기반 변경 검토를 선택해 Slack 또는 Discord 입력, Sheets/Slack 출력으로 바뀐 그래프를 보여줍니다. 이 프리셋은 기존 배송 변경 검토 계약을 사용하며 내부 사례 문안은 배송 예시입니다.
6. 선택사항: Slack 첫 시도 실패 모의 → 실행/승인 → 실패 액션만 재시도. 기존 성공 액션이 재실행되지 않음을 확인합니다.
7. 오래된 차량 데이터 또는 알 수 없는 상태를 넣어 차단을 보여줍니다.

### 정직한 시연 설명

“로컬 워크플로우 엔진의 설정·활성화·조건 평가·승인·결과 기록을 실행하는 데모입니다. 외부 서비스와 차량의 입력은 모의 데이터이며, 실제 LLM·외부 API는 미연결입니다. 승인 이후에는 실제 로컬 브리지로 공식 PLEOS 에뮬레이터 앱에 업무를 배정하고, 앱이 읽은 AAOS 상태 및 완료 결과를 같은 실행 ID로 확인합니다.”

## 범위

- **실행됨:** 기존 로컬 백엔드와 실제 HTTP API 연결, 검증된 두 계약 설정/버전/조건/승인/이력/실패 재시도.
- **모의:** Google Calendar/Slack/Discord 이벤트, Sheets 데이터, PLEOS 상태, 문안 생성, Kakao/Slack 출력. 자율 Agent가 아니며 문안은 결정론적 템플릿입니다.
- **실제 로컬 연결:** 승인된 실행 → 네이티브 배정 API → 공식 PLEOS 2.1.0 앱 → AAOS 속도/기어/UX 제한 확인 → 운전자 승인/완료 → 같은 실행 ID로 Studio 완료 회신.
- **미연결:** OAuth/실제 메시지/실제 LLM/내비 명령/실차 제어.
- 문안 생성은 실행 권한이 없습니다. 사용자 검토 후 로컬 액션만 기록합니다.
- 모든 테스트 데이터는 가상입니다. 계정/비밀키/실제 고객 정보 입력 기능 없음.
- 인증 없는 로컬 데모이므로 공개 인터넷에 노출하지 마세요.

## 검증

2026-11-15 클라우드: 기존 322개 + 새 Studio 2개 자동 테스트, JS 문법 검사. 새 Studio 테스트는 HTTP 정적 파일 제공, 두 계약의 실행·승인·실패 재시도·unknown-state 차단·외부 전송 없음 확인을 포함합니다.
